# Design Context

### Users
Dealership appraisal staff at **CarWow WA** (a Perth used-car dealer). They pre-vet
many cars a day — at a desk or on a phone in the yard — and need a fast, defensible
**max offer** and a **Buy / Pass / Check** verdict they can stand behind, then route
for human review. Pragmatic, repeat users; speed and trust matter more than delight.

### Brand Personality
Precise · trustworthy · utilitarian. A **trade instrument**, not consumer fintech.
The interface should feel like a well-made appraisal docket / inspection report:
calm, exact, and auditable.

### Aesthetic Direction
**Instrument / appraisal-docket.** Locked, deliberate choices (refine, don't reinvent):
- **Type:** IBM Plex Sans (UI) + IBM Plex Mono (every figure, plate, ledger,
  tabular number). *This is a deliberate, locked brand choice — keep it even though
  generic guidance would swap it.*
- **Color:** neutral monochrome theme; **status hues only where they carry meaning** —
  Buy = emerald, Check = amber, Pass = rose. Tokens in `src/lib/verdict-style.ts`.
- **Light + dark**, system preference + a toggle (already wired).
- **Anti-references:** consumer-fintech gloss, gradients/gradient text, glassmorphism,
  neon-on-dark, decorative side-stripe borders, card-in-card.

### Design Principles
1. **The number must be checkable.** Always show the math (the subtraction ledger);
   never a black-box figure.
2. **Spend boldness once.** The colored verdict band is the single loud element;
   everything around it stays quiet.
3. **Mono for data, sans for prose.** All figures use IBM Plex Mono + tabular-nums.
4. **Status color = meaning only.** Emerald/amber/rose signal Buy/Check/Pass; neutral
   everywhere else.
5. **Refine, don't reinvent; no new dependencies.** Hand-built shadcn (radix-nova)
   primitives in `src/components/ui`; reuse the existing token system.
